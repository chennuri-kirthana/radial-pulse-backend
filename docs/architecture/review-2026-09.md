# Architecture review — September 2026 (updated product decisions)

We reviewed the Phase 0 repo against the updated product decisions and the Central Tech scope.
Rule we followed: **simple + correct beats complex + future-proof.** We only built what the
current product needs. Everything else is written down with a reason.

Legend: **REQUIRED** (built now) · **DEFER** (important, documented, not built) ·
**NOT REQUIRED** (rejected) · **COVERED** (the repo already does this).

## A. Implemented now

1, 2, 3, 4 (boundary), 5, 6 (worker), 7, 8, 9 (profiles), 12, 25 — plus the updates they force in 18, 19, 20, 21, 22, 23, 24.

## B. Documented for later

4 (engines), 6 (HTTP service-to-service auth), 10 (provider implementations), 11 (crawler),
13 (chat), scheduled re-assessments (EventBridge Scheduler), separate AWS accounts, RLS on
identity tables.

## C. Not implemented, on purpose

- **A general "AI agent framework"** — the engine interface is enough.
- **One queue per job type / Step Functions / Kafka** — one queue with typed messages covers
  current volume.
- **Separate tables per social platform** — one table with a `platform` column.
- **Per-report-type user-facing reports** — rejected by the product decision.
- **WebSocket infrastructure** — no live feature needs it yet.
- **Switching Aurora → RDS** — no reason; Aurora is already built and cheaper when idle.
